# 文献综述与追踪

> 适用对象：AI + 低空经济安全方向硕士生。主线 T1 论文《Explainable Decision-Credibility Monitoring for IDS in UAV Ad Hoc Networks: Graph-Augmented Dual-Layer AI Trust Framework》（创新点 N1–N5），目标 SCI Q2、IF≥7（IEEE T-ITS 8.4 / Digital Communications and Networks 7.5），Q1 冲刺。
> 本模块只解决一件事：**把别人做过什么摸清楚，并保持持续跟进**。创新点是否成立属于 `02-innovation.md` 的职责，不在此处判断。

## 什么时候用

1. 立题或换子方向时，需要确认"这个坑有没有人填过、填到什么程度"。
2. 用户说"UAV 入侵检测现在都用什么方法""可解释 IDS 近两年有什么新东西""帮我查一下 UAV 信任评估的最新进展"。
3. 动笔写 Related Work / Introduction 第二段之前，需要一份可引用的、按主题组织而非按论文罗列的文献底稿。
4. 投稿前做 scoop 风险排查：确认近 6 个月内没有与目标方法高度重叠的正式发表论文。
5. 收到审稿意见"请与 XXX 方法比较""缺少近三年文献"，需要快速定位并补引。
6. 进入长周期（≥3 个月）写作或返修期，需要每周固定追踪新增文献，避免 Related Work 写完即过期。

**不触发的场景**：要论证"我比别人新在哪"走 `02`；要跑实验、画图、写正文段落走对应写作模块。

## 输入与输出

**输入（需用户提供）**

| 项 | 说明 | 缺省处理 |
|---|---|---|
| 主题词表 | 中英文对照的检索词、同义词、缩写（如 UAV Ad Hoc Network / FANET / UANET / 无人机自组网） | 从 T1 标题拆词，让用户确认后再跑 |
| 目标期刊列表 | 用于限定 venue 与判断相关工作层级 | 默认 IEEE T-ITS、DCN、IEEE TII、IEEE TNSE、Computer Networks |
| 时间窗 | 起始年份与截止日期 | 默认 2019 至今，重点加权 2023 年后 |
| seed 论文 | 3–10 篇已知核心论文（DOI 或 bibtex） | 用于滚雪球（前向/后向引用） |
| 排除词 | 明确不相关的词（如"卫星网络""水下声呐"） | 用户未给则跑完第一轮后按其标注反推 |

**输出目录约定**

```
research-agent/literature/
  raw/        检索原始结果，每次检索一个文件，文件名含日期与检索式编号
  matrix/     对比矩阵（ra_matrix.py 产出）与主清单
  notes/      精读笔记，一篇一文件
  tracking/   每周追踪周报
  bib/        去重合并后的 .bib
  review/     综述成稿（Related Work 底稿、年度进展备忘）
```

## 工作流

### 步骤 1｜构造检索式并冻结
做什么：把主题拆成 **A（场景）× B（方法）× C（问题）** 三个维度，每组写中英文词、同义词、缩写，交叉组合成 6–12 条检索式；给每条编号（Q01…Q12），记录数据源与时间窗。
用什么工具：人工构造 + `python scripts/ra_search.py --query "<query>"` 试跑，观察命中量后微调；`python scripts/ra_profile.py --recommend` 在不确定子方向优先级时辅助排序。
产出：`research-agent/literature/raw/queries.md`（检索式总表，含编号、表达式、数据源、命中数、执行日期）。
判定：单条检索式命中量应落在 30–300 篇区间；<20 说明过窄需加同义词，>500 说明过宽需加限定词或限定 venue。

### 步骤 2｜批量检索与落盘
做什么：按检索式编号逐条执行，原始结果全量落盘不做筛选；同时用 seed 论文做前向（谁引了它）与后向（它引了谁）滚雪球。
用什么工具：`python scripts/ra_search.py --query "<query>" --years "<start>-<end>" --out "<raw/路径>"`；滚雪球用 `python scripts/ra_search.py --query "<seed doi 或 title>"`。
产出：`raw/` 下按检索式分文件的结果集（含标题、作者、年份、venue、DOI、摘要、被引数）。
判定：所有文件必须带检索式编号与执行日期，否则后续无法复现；被引数单独成列、不参与本轮排序。

### 步骤 3｜三级漏斗筛选
做什么：
- **L1 标题层**：去重（DOI 归一化 + 标题模糊匹配），剔除明显跨领域命中；
- **L2 摘要层**：按"是否同时命中 A×B 或 B×C"判断，只保留二维以上命中的论文；
- **L3 全文层**：对存活文献精读 Introduction、Method、Dataset、Conclusion 四段，判定是否进入主清单。
用什么工具：L1/L2 人工 + `python scripts/ra_matrix.py --input "<raw/路径>"` 聚合成待筛清单；L3 精读，笔记写入 `notes/`。
产出：`matrix/candidate-list.md`（候选池，标注 L1/L2/L3 状态与淘汰理由）。
判定：淘汰必须写明一句理由，禁止静默删除；每个 L2 淘汰项都要能被用户抽查复核。

### 步骤 4｜生成文献对比矩阵
做什么：对进入主清单的论文，逐篇抽取六列字段填入矩阵；按"方法族"分组（如：图神经网络类 / 联邦学习类 / 信任评估类 / 可解释 XAI 类 / 传统机器学习类），组内按年份排序。
用什么工具：`python scripts/ra_matrix.py --input "<candidate-list 路径>" --output "<matrix/路径>"`，生成后人工补齐"局限"与"与本文关系"两列（脚本只能辅助结构化，判断必须人工）。
产出：`matrix/literature-matrix.md`（见输出模板）+ `matrix/coverage-check.md`（覆盖度检查：每个方法族是否 ≥3 篇、2023 年后是否 ≥40%）。
判定：矩阵中"局限"列不得出现"未考虑安全"这类空话，必须指向具体技术缺陷（如"仅静态拓扑，未处理链路频繁断裂"）。

### 步骤 5｜精读与局限抽取
做什么：对矩阵中标记为"强相关/直接竞品"的论文逐篇精读，抽取四类信息：① 它用的数据集与指标；② 它的核心假设（往往就是局限的来源）；③ 它自己 Conclusion 里承认的 future work；④ 它的实验是否覆盖动态拓扑/机载算力约束。
用什么工具：`python scripts/ra_search.py --query "<title>"` 补齐引用关系；笔记写入 `notes/`。
产出：`notes/<第一作者><年份><关键词>.md`，统一模板（见输出模板）。
判定：每篇笔记必须能回答"如果审稿人拿这篇说我增量不足，我怎么回"——答不上来说明精读不到位。

### 步骤 6｜按主题成稿（非按论文罗列）
做什么：把主清单按"主题线索"重组为综述底稿。推荐线索（适配 T1）：UAV 网络攻击面与威胁模型 → IDS 检测方法演进（规则→ML→DL→图模型）→ 信任评估机制 → 可解释性在安全场景的应用 → 机载/边缘部署约束。每条线索内部做"演进式"叙述（谁解决了什么、留下了什么），线索末尾用一句话点出本文切入点。
用什么工具：人工写作，矩阵作为事实来源；`python scripts/ra_matrix.py --input "<matrix 路径>"` 导出分组视图辅助。
产出：`review/related-work-draft.md`，直接可嵌 Related Work；`review/landscape-memo.md` 年度进展备忘。
判定：全文不得出现"作者提出了…作者提出了…"的流水账句式；每条线索必须有明确的"遗留问题"收束。

### 步骤 7｜建立每周追踪
做什么：固定每周执行一次增量检索，只用步骤 1 冻结的检索式（保证可比），限定新增时间窗，输出增量清单并按"是否冲击本文定位"打标（红/黄/绿）。
用什么工具：`python scripts/ra_track.py --query "<query>" --since "<YYYY-MM-DD>" --out "<tracking/路径>"`；多条检索式逐条执行后合并。
产出：`tracking/YYYY-WW.md` 周报（新增 N 篇、红色预警 M 篇、对本论文影响判断）。
判定：周报必须包含"是否需要修改本文定位/是否需要补做对比实验"的明确结论；无新增也要留档，避免断档无法证明追踪连续性。

### 步骤 8｜回填与版本化
做什么：把周报中的新增相关文献回填进主矩阵与 `.bib`，重新跑覆盖度检查；每月做一次矩阵快照，保留历史版本以便返修时证明"投稿时该工作尚未发表"。
用什么工具：`python scripts/ra_matrix.py --input "<主清单路径>" --output "<matrix/路径>"`；`bib/` 目录去重合并。
产出：更新后的 `matrix/literature-matrix.md`、`bib/main.bib`、`matrix/snapshot-YYYYMM.md`。
判定：快照文件名含日期；任何一次投稿/返修提交前必须存在一份当月快照。

## 质量清单

1. 每条检索式都同时覆盖"场景词 × 方法词"或"方法词 × 问题词"，不存在单维度宽泛检索。
2. 单条检索式命中量在 30–300 篇区间，超出区间的已加词或加限定条件重跑。
3. 主清单覆盖至少 5 个方法族，每个方法族不少于 3 篇。
4. 主清单中 2023 年及以后的文献占比不低于 40%，2024 年后不少于 20%。
5. 主清单中至少包含 2 篇目标期刊（IEEE T-ITS / DCN）近三年同主题论文，用于判断期刊偏好。
6. 矩阵"与本文关系"列每一格都明确标注为：直接竞品 / 对比基线 / 前置工作 / 背景引用 四类中之一。
7. 被标记为"直接竞品"的论文，每篇都已精读并产出 `notes/` 笔记，且笔记中"若被质疑"栏非空。
8. 矩阵"局限"列无空话（禁止出现"未充分考虑""有待提高"等无信息量表述），每条局限指向具体技术点。
9. 已排查近 6 个月是否出现与本文方法高度重叠的正式发表论文，结论写入最近一期周报。
10. `bib/main.bib` 已去重（DOI 归一化），且每条含 DOI、venue、年份、页码。
11. 最近一次投稿或返修前存在当月 `matrix/snapshot-YYYYMM.md`。
12. 追踪周报连续无断档，任意相邻两周的 `since` 日期连续可拼接。

## 常见坑

1. **只看摘要就下结论**。安全类论文摘要普遍夸大，方法的真实约束（固定拓扑、离线训练、单机检测）往往藏在实验配置里。判"与本文关系"前必须读 Method 与实验设置两段。

2. **被引数不等于相关度**。高被引常是综述或老方法基准，反而最新最强竞品因发表不足一年而被引个位数。排序时按相关度和时间加权，不要按被引排序。

3. **arXiv 预印本与正式版存在实质差异**。同一篇论文预印本的方法、实验甚至标题都可能与正式版不同；引用正式版，追踪时看预印本。引用前必须核对 DOI 对应版本，并在笔记中标注所读版本与日期。

4. **把非 UAV 场景论文当 UAV 论文引用**。CICIDS2017、NSL-KDD、KDD Cup 99 是有线/通用网络数据集，部分论文用它却声称面向 UAV。引用时必须核对数据集是否真是 UAV/FANET 场景，否则会被审稿人当场指出。

5. **数据集名称写法不统一导致漏检**。同一数据集存在多种写法（如 UAV-IDS-2020 / UAVIDS / UAV Intrusion Dataset），检索式必须把这些变体全部列出，否则系统性漏掉一整支工作。

6. **中文数据库与英文数据库结果割裂**。国内 UAV 安全团队常发中文核心期刊或会议，内容可能与本文重叠但从未进入英文检索。至少做一轮中文检索（知网/万方）交叉验证。

7. **只检索不追踪，Related Work 写完即过期**。本文目标期刊周期长，从写作到返修常跨 6–12 个月。必须用 `ra_track.py` 固定周频执行，并保留快照，才能在返修时证明"投稿时该工作尚未发表"。

8. **把滚雪球当主检索**。滚雪球会顺着 seed 论文已有引用链走，天然偏向旧文献和同一学派，容易漏掉新出现的跨领域方法。滚雪球只能作为补充，主检索必须用冻结检索式。

9. **综述写成论文流水账**。按论文逐篇罗列"张三提出了…李四提出了…"无法通过审稿。必须按主题线索重组，每条线索以"遗留问题"收束，并自然导向本文切入点。

10. **忽略会议论文与期刊版本的重复计数**。同一工作先发会议（如 IEEE GLOBECOM / ICC）再扩成期刊，会在结果集中出现两次且标题相近。去重时按内容合并，引用时优先期刊扩展版。
