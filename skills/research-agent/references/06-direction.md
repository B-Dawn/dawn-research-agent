# 个人画像驱动的研究方向推荐

面向「下一批做什么方向」，核心约束是**不浪费已有积累**。
本模块不处理"这篇稿子投哪里"（见 `05-submission.md`）。

默认用户画像（写入 `profile/researcher-profile.md`，本模块全部决策以此为锚）：

- 身份：GLOBAL AI 方向硕士研究生，毕业时间表固定且不可延后
- 主研究方向：AI + 低空经济安全（UAV / 低空智联网 / UAV Ad Hoc Networks）
- 主推 T1 论文：Explainable Decision-Credibility Monitoring for IDS in UAV Ad Hoc Networks（N1–N5 五创新点）
- 目标：SCI Q2、IF≥7
- **三线并行**：科研 / 教材《网络空间安全导论》/ 长篇小说写作，每周可投入科研的时间是硬约束
- 因此：**时间成本是一个显式评分维度，与热点程度同级**

## 什么时候用

1. T1 已投或接近收尾，需要决定"下一篇文章做什么"，用户问："接下来做啥？""还有没有能发的点？"
2. 手上有一堆零散想法，需要排序，用户问："这几个方向哪个值得做？"
3. 看到某个新热点（如低空经济的某项新标准、某个新架构），用户问："这个跟我有关吗？要不要追？"
4. 需要判断某个方向能不能复用已有的代码、数据集、实验框架，避免从零开始。
5. 需要评估某个方向从开题到可投稿要多久，判断能否塞进毕业时间表。
6. 教材写作中遇到某个章节主题，想顺手转成一篇可投稿的论文，问："这章能变成论文吗？"

## 输入与输出

输入：

| 输入项 | 位置 | 说明 |
| --- | --- | --- |
| 研究者画像 | `profile/researcher-profile.md` | 方向、已发表/在投工作、技能模块、时间预算 |
| 期刊事实表 | `assets/journals.json` | 判断候选方向的目标刊是否存在、IF 是否达标 |
| 领域热点 | 检索结果（见工作流第 3 步） | 近 12–24 个月的会议/期刊/标准动态 |
| 可选：在投稿件指纹 | `workspace/submission/<journal>/fingerprint.json` | 用于避免与在投工作自我重复 |

`profile/researcher-profile.md` 必须包含以下四节，脚本按节名解析：

```
## 方向          # 主方向 + 副方向 + 明确不做的方向
## 已发表/在投工作  # 题目、状态、期刊、核心方法、可复用资产（代码/数据/框架）
## 技能模块        # 见下文交叉矩阵，条目化、可枚举
## 时间预算        # 每周可投科研小时数、毕业截止、不可占用时段
```

输出（统一写入 `workspace/direction/`）：

- `candidate-directions.md` —— 候选方向评分表 + 推荐等级 + 淘汰理由
- `reuse-matrix.md` —— 「技能模块 × 领域需求」交叉矩阵
- `first-actions.md` —— 方向 → 首个可行动作映射
- `time-budget.md` —— 每个推荐方向的分阶段时间估算与里程碑

## 工作流

### 第 1 步：解析画像，抽取可复用资产

做什么：把画像里的"已有积累"拆成**四类可枚举资产**，方向推荐只在这四类资产的组合上做文章。
用什么工具：Read 读 `profile/researcher-profile.md`。

四类资产：

1. **技能模块**：GNN/图表示学习、IDS 建模、可解释 AI（XAI）、双层/分层框架设计、在线监控与漂移检测、对抗样本与鲁棒性、网络仿真（NS-3/OMNeT++/UAV 仿真）、形式化/可信度度量
2. **数据资产**：公开 UAV/无人机网络数据集、自采仿真数据集、已标注的攻击流量集
3. **代码资产**：GNN 训练管线、IDS baseline 实现、XAI 解释模块、仿真场景配置
4. **叙事资产**：N1–N5 五条创新点（每条都可被延展为独立论文）、教材章节、已积累的写作素材

产出：`workspace/direction/assets-inventory.md`，四类资产的清单，每条标注"成熟度（可直接用 / 需改造 / 需新建）"。

### 第 2 步：构造「技能模块 × 领域需求」交叉矩阵

做什么：把用户会做的事，和低空经济安全领域**当前真实存在的需求**做交叉，从交叉格里长出新方向，而不是从热点清单里挑。
用什么工具：Read 读画像 + WebSearch 检索领域需求。

**矩阵的构造方式（本模块的核心，严格按此执行）：**

1. **行 = 用户技能模块**。行来自第 1 步的清单，一行一个技能，不合并、不泛化。技能名必须对应画像里真实存在的条目。
2. **列 = 领域需求**。列**不是**热搜词，而是低空经济安全产业链上的真实缺口，来源必须是可核查的：
   - 标准与法规：民用无人机相关国家标准、行业标准、适航与运行安全要求中尚未被技术手段覆盖的条款
   - 产业痛点：低空物流、城市空中交通、无人机集群作业中公开的故障/事故/安全事件类型
   - 学术空白：近 12 个月综述论文（包括自己写的教材章节）中明确点名为 open problem 的条目
   每列必须标注来源（标准号 / 事件 / 论文出处），**无来源的列直接删掉**。
3. **填格子**。每格填三选一：
   - `直用` —— 现有技能可直接解决该需求，几乎不需新方法
   - `改造` —— 需 20%–50% 的新工作（新数据集 / 新模块 / 新指标）
   - `空白` —— 技能与需求无关，或需要从头学
   空格（`空白`）在后续步骤中**不得**生成候选方向。
4. **读格子**。候选方向只从 `直用` 和 `改造` 格里产生，且优先 `直用`：
   - 单个 `直用` 格 = 一个方向雏形
   - 相邻两个 `直用` 格 = 更强的方向（说明有组合创新，比单点更容易过 Q2）
   - 全 `空白` 的列 = 该需求不适合此用户，**明确写进淘汰理由**，不因为"很热"而保留

产出：`workspace/direction/reuse-matrix.md`，Markdown 表格 + 每个 `直用`/`改造` 格的一句话说明。

矩阵示例（仅为格式示意，实际内容由检索结果填充）：

| 技能模块 \ 领域需求 | 需求A：<来源> | 需求B：<来源> | 需求C：<来源> |
| --- | --- | --- | --- |
| GNN / 图表示学习 | 直用 | 改造 | 空白 |
| IDS 建模 | 直用 | 直用 | 空白 |
| 可解释 AI | 改造 | 直用 | 空白 |
| 网络仿真 | 直用 | 改造 | 直用 |

### 第 3 步：交叉检索热点

做什么：拿着矩阵产生的方向雏形去检索，验证"热不热、空不空"。
用什么工具：WebSearch / WebFetch。

```
python scripts/ra_profile.py --recommend --profile profile/researcher-profile.md --matrix workspace/direction/reuse-matrix.md --max <5> --out workspace/direction/candidate-directions.md
```

脚本读取 `profile/researcher-profile.md` 中的**方向、已发表/在投工作、技能模块**三节，与矩阵结果做交叉，输出候选方向初筛。
检索动作独立于脚本进行，用于为初筛结果回填"热点程度"与"数据可获得性"两列：

- 近 12 个月顶会/期刊中该主题的论文增长趋势（上升 / 平稳 / 已饱和）
- 是否存在公开数据集；若需自采，估算采集与标注工作量（人天）
- 是否已有人做过完全相同的事（撞车检测）：找到 3 篇以上高度相似即判为红海

产出：回填后的候选方向列表，每条附来源链接与检索日期。

### 第 4 步：时间成本建模（本模块强制项）

做什么：给每个候选方向估算**从今天到投稿**的时间，并与毕业时间表做减法。
用什么工具：Read 读 `profile/researcher-profile.md` 的时间预算节。

分阶段估算，每阶段单独给小时数，不写"大概三个月"：

| 阶段 | 估算内容 |
| --- | --- |
| 文献与定位 | 精读论文数 × 单篇耗时 |
| 数据获取 | 公开数据集下载清洗 / 自采仿真场景搭建 |
| 方法实现 | 复用代码比例 → 需新写的模块数 |
| 实验与 ablation | 实验组数 × 单次运行时长 |
| 写作 | 复用叙事资产（教材章节、N1–N5 素材）可省下的时间 |
| 投稿与返修 | 一轮返修的常规耗时 |

**时间成本与复用度强相关**：复用度 80% 的方向与复用度 30% 的方向，实际耗时可差 3 倍以上。因此时间成本不是独立维度，必须由第 1 步的资产清单推导。

产出：`workspace/direction/time-budget.md`，每个方向一张时间表，末尾给出"是否塞得进毕业时间表"的二元结论。

### 第 5 步：打分与排序

做什么：按六个维度打分，产出推荐等级。
用什么工具：`python scripts/ra_profile.py --recommend` 的输出 + 人工回填列。

权重（时间成本权重被刻意调高，因为用户三线并行）：

```
score = 0.25 * 复用度        # 越高越好，越高越省时间
      + 0.20 * 时间成本得分    # 出成果周期越短得分越高；塞不进时间表直接 0 分
      + 0.20 * 热点程度        # 上升期最高，已饱和期最低
      + 0.15 * 数据可获得性    # 公开数据集 > 可自采 > 需外部合作
      + 0.10 * 目标刊可达性    # 该方向是否存在 IF≥7 的 Q2 期刊落点（查 assets/journals.json）
      + 0.10 * 反重叠          # 与在投/已发表工作的差异度，避免自我重复
```

推荐等级：`A（立即启动）/ B（备选项）/ C（观察，暂不动）/ X（淘汰，写明理由）`。

### 第 6 步：裁剪到 5 个以内

做什么：硬截断。
规则：最终呈现的候选方向**不超过 5 个**，其中 A 级不超过 2 个（用户三线并行，同时推进 2 个以上等于都不推进）。

裁剪顺序：先砍 C 与 X，再按 score 砍到 5，最后检查 A 级是否 ≤2；若 A 级有 3 个，把其中复用度最低的降为 B。

产出：`workspace/direction/candidate-directions.md` 最终版。

### 第 7 步：生成首个可行动作

做什么：每个推荐方向配一个**当天或本周内可执行**的动作，禁止"进一步调研文献"这种不可判定的动作。
动作必须是下列类型之一：跑通一段已有代码 / 下载并加载一个数据集 / 写出一段可运行的最小实验 / 写一页 300 字的问题定义 / 给某篇论文的作者发一封邮件。

产出：`workspace/direction/first-actions.md`。

### 第 8 步：回写画像

做什么：把采纳的方向写入 `profile/researcher-profile.md` 的"在投工作"或新增"规划中"一节，并更新技能模块清单（新方向会产出新技能）。
用 Edit 追加，不覆写。

## 质量清单

1. 每个推荐方向必须能复用用户至少一项已有技能或数据；复用度为 0 的方向一律判 X 级，不进入表格。
2. 推荐数不超过 5 个，A 级不超过 2 个；超出即视为裁剪失败，需重跑第 6 步。
3. 交叉矩阵的每一列（领域需求）都标有可核查来源（标准号 / 事件 / 论文出处）；无来源的列已删除。
4. 每个候选方向都给出**分阶段时间估算**（小时数），且末尾有"是否塞得进毕业时间表"的二元结论。
5. 每个候选方向都写有**终止条件**，不存在"无限期推进"的方向。
6. 数据可获得性不是空话：公开数据集给出名称与获取方式；需自采的给出了人天估算。
7. 已做撞车检测：对每个 A 级方向，明确列出检索到的最相似工作 ≥3 篇，并说明本文差异。
8. 每个 A/B 级方向都能在 `assets/journals.json` 中找到 IF≥7 的 Q2 落点；找不到的降为 C 级。
9. 与用户在投/已发表工作的重叠度已被检验，不存在可能构成自我重复的方向被列为 A 级。
10. 首个可行动作是可判定的（有明确产出物与通过标准），不含"进一步调研""深入学习"这类无法验收的表述。
11. 评分表中的复用度百分比有资产清单支撑，不是拍脑袋估值。
12. 采纳的方向已回写 `profile/researcher-profile.md`，并同步更新技能模块清单。

## 常见坑

1. **推荐完全陌生的方向导致沉没成本。** 用户三线并行，一个需要从头学 3 个月新方法的方向，等于直接吃掉教材和小说的时间，且很可能最终既不毕业也不出成果。矩阵中的 `空白` 格永远不生成候选方向，这条是硬规则。
2. **把热点当方向。** "低空经济"四个字底下有几十个细分问题，热点只是信号，不是选题。选题必须落到矩阵的一个具体格子上：我的哪个技能，解决谁的什么需求。
3. **忽略数据可获得性。** 构思时默认"数据总能搞到"，动手后发现 UAV 网络攻击数据集要么不存在、要么标注质量差、要么需要合作方授权。数据这一列必须在动手前查实，否则整个方向在第三周崩盘。
4. **不做时间建模，只看"这个方向好不好"。** 好方向很多，塞不进毕业时间表的都不是方向。时间成本是本模块的显式评分维度，权重高于热点程度，不要因为某个方向"很前沿"就放宽时间约束。
5. **同时推进 3 个以上 A 级方向。** 三线并行的真实产能是每周有限小时数，多线并行会导致每条线都停在 60%，最后一条都投不出去。A 级硬上限 2 个。
6. **与在投稿件自我重复。** 下一个方向如果和 T1 的 N1–N5 在方法、数据集、结论上高度重叠，投出去会被判 self-plagiarism，甚至牵连在投稿件。反重叠占 10% 权重就是为了拦这个。
7. **没有终止条件。** 一个方向做两个月发现数据集不可用还不肯放弃，是最典型的沉没成本陷阱。每个方向在启动前就要写死放弃信号。
8. **把教材章节直接当论文。** 教材是"已有知识的系统陈述"，论文是"一个未被解决的具体问题的新解"。教材章节可以转化为论文的**问题定义与背景**（这是复用叙事资产的正确用法），但必须补上原创贡献与实验，不能直接投稿。
9. **只看顶会不管期刊落点。** 用户目标是 SCI Q2、IF≥7，不是顶会。一个只适合投顶会 workshop 的方向，对毕业没有直接帮助，落点检查（第 8 条质量清单）就是为了筛掉这类。
