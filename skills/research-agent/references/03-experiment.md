# 实验辅助与出图

> 适用对象：AI + 低空经济安全方向硕士生，主线 T1 论文《Explainable Decision-Credibility Monitoring for IDS in UAV Ad Hoc Networks: Graph-Augmented Dual-Layer AI Trust Framework》（N1–N5）。
> 本模块只解决一件事：**把实验跑对、记全、画清楚**。创新点该由哪组实验证明属于 `02-innovation.md`，怎么把结果写成章节正文属于 `04-writing.md`。
> 环境约束：Windows，Python 脚本**零第三方依赖（仅标准库）**，因此绘图产物是 **SVG**，不弹 matplotlib 窗口，不出 PNG（除非另配转换工具）。

## 什么时候用

1. 准备开一组新实验，需要先定假设、对照组、指标口径，而不是直接改代码跑。
2. 用户说"我这个结果能不能用""帮我画个对比图""这个表和正文对不上"。
3. 要把 N1–N5 每个创新点对应到一组可单独证明其贡献的消融实验。
4. 多次运行结果波动大，需要判到底是随机性还是方法真的有效。
5. 投稿前整理 Experiments 章节素材：主表、消融表、参数敏感性、开销表、可视化图。
6. 审稿人要求 "more baselines / statistical significance / complexity analysis / scalability"，需要补实验。
7. 结果失控或与预期相反，需要判断是 bug、超参还是假设本身错了。
8. 复现自己三个月前的结果却复现不出来，缺配置快照与随机种子记录。

**不触发的场景**：查文献走 `01`；论证创新点走 `02`；写章节正文走 `04`。

## 输入与输出

**输入（需用户提供）**

| 项 | 说明 | 缺省处理 |
|---|---|---|
| 实验假设 | 一句话：在 <条件> 下，<做法> 相比 <对照> 使 <指标> 变化 <方向> | 必填，缺则不许开跑，退回先写假设 |
| 数据集与划分 | 名称、规模、train/val/test 划分方式与比例、预处理 | 缺则标注 `TODO`，台账状态记为 `blocked` |
| 代码与配置 | 可运行入口、超参文件、随机种子、运行次数 | 必填，配置需快照留档 |
| 基线方法 | 名称 + 出处 + 复现方式（官方代码 / 自实现 / 引原论文数值） | 缺官方代码时须在台账注明"自实现" |
| 指标口径 | 精确定义、计算脚本、正负例定义、多类场景是 macro 还是 micro/weighted | 缺则先冻结口径再跑，禁止事后改口径 |

**输出目录约定**

```
output/experiments/
  ledger/         实验台账（ledger.md，单一事实来源，所有实验先登记后执行）
  configs/        每次运行的配置快照 <exp_id>.<run_id>.yaml/json（含 seed）
  raw/            原始输出：逐 run 的 log、预测、逐样本结果，不做任何聚合
  results/        聚合后的结果 CSV（唯一绘图数据源），metrics.csv / ablation.csv / sensitivity.csv
  figures/        SVG 图件 + 同名 .caption.md 图注
  tables/         论文表格源文件（Markdown/CSV），与主表编号对齐
  notes/          失败/异常记录，含 negative result 归档
```

## 工作流

### 步骤 1｜登记实验台账，先拿实验 ID
做什么：任何实验在写代码之前先在 `ledger/ledger.md` 建一行，领取 `实验ID`（命名 `E<序号>-<简短主题>`，如 `E07-N3-ablation`），并把假设、数据集、指标、状态写死。状态只用四值：`planned / running / done / abandoned`。
用什么工具：文本编辑台账；`python scripts/ra_plot.py` 不涉及本步。
产出：`ledger/ledger.md` 新增一行，`configs/<exp_id>.plan.md` 写清假设与判定标准（涨/跌多少算假设成立）。
判定：没有实验 ID 的运行结果一律不进 `results/`，不进论文；`abandoned` 的行不许删，它是 negative result 的证据。

### 步骤 2｜设计对照组与消融，对齐 N1–N5
做什么：把实验拆成四类并分别登记——(a) 主实验：本文 vs 全部 baselines；(b) 消融实验：逐个摘除 N1–N5 对应模块，一次只摘一个；(c) 敏感性实验：超参（如图层数、信任阈值 τ、GNN 隐层维度）扫点；(d) 鲁棒性/开销实验：噪声、拓扑密度变化、推理时延与显存。
用什么工具：人工设计；对照表与 `02-innovation.md` 的 `ablation/` 目录交叉核对，确保五个创新点各有一组独立消融，不存在"两条 claim 共用一组消融"。
产出：`ledger/ablation-map.md`，表结构 `创新点 / 对应模块 / 消融变体名 / 实验ID / 预期指标变化 / 若不变则说明什么`。
判定：任一条 claim 找不到独立实验 ID，说明该 claim 尚未被证明，回 `02` 重拆。

### 步骤 3｜冻结配置与随机性
做什么：固定 seed（训练/数据划分/数据加载/丢弃顺序各一个）、固定运行次数（主实验 ≥3 次，消融 ≥3 次，开销类 ≥5 次取均值）、固定数据划分文件而非每次随机切。把完整配置连同环境版本（Python 版本、关键库版本是否可用、CUDA/CPU）写入快照。
用什么工具：文本/配置快照；`configs/<exp_id>.<run_id>.yaml` 一个 run 一个文件，禁止覆盖。
产出：`configs/` 下按 run 粒度的快照，台账 `超参` 列填入摘要 + 快照文件名。
判定：任何一个能影响结果的变量（含"忘了关的 data augmentation"）没写进快照，该 run 作废重跑。

### 步骤 4｜执行并落盘原始输出
做什么：只跑，不分析。每个 run 输出独立目录，落盘逐样本预测与日志，保留失败 run 的完整报错。禁止在内存里挑数字，禁止边跑边改超参。
用什么工具：用户自有训练/评估代码；输出重定向到 `raw/<exp_id>/<run_id>/`。
产出：`raw/<exp_id>/<run_id>/{run.log, metrics.json, predictions.csv, error.log?}`。
判定：`metrics.json` 缺失或 `error.log` 非空的 run 标记 `abandoned` 并在 `notes/` 写原因，不得静默丢弃。

### 步骤 5｜统一口径后聚合
做什么：按步骤 1 冻结的口径计算指标，跨 run 聚合出 **mean ± std**（非最大值的单次结果），并按同一口径重算所有 baselines——**自家方法用自实现指标、基线抄原论文数值**是最常见的口径污染，必须全部用同一份脚本重算，抄来的数值单独一列标注来源。
用什么工具：标准库 Python 聚合脚本或手工核；输出统一进 `results/`。
产出：`results/metrics.csv`、`results/ablation.csv`、`results/sensitivity.csv`，列名见下方模板，一行 = 一个 (方法, 数据集, 指标, run) 观测。
判定：CSV 里不得出现派生数值（如"提升百分比"），派生量留给绘图/制表时算，避免二次污染。

### 步骤 6｜出图（SVG）
做什么：只从 `results/*.csv` 取数绘图，绝不用手抄数字画图。先跑 `python scripts/ra_plot.py --help` 确认可用参数，再按 help 填参执行；该脚本**只依赖 Python 标准库**，读取 CSV、输出 SVG，无窗口、无 matplotlib。
用什么工具：

```bash
python scripts/ra_plot.py --help                  # 先确认参数，不要凭记忆写
python scripts/ra_plot.py <绘图参数>              # 输入 results/<...>.csv，输出 figures/<...>.svg
```

产出：`figures/<exp_id>-<图类型>.svg` + 同名 `<图名>.caption.md`（图注正文，含每个子图一句话结论）。
判定：图件必须通过下方"出图自检"；SVG 可用浏览器或矢量编辑器打开核字，禁止截图后二次压缩导致坐标轴文字糊掉。

### 步骤 7｜显著性判断
做什么：对主实验关键指标做差异判断——多次运行的 std 是否让两组误差棒重叠；样本级指标（如逐样本 F1）可做配对比较。不要只报 p 值，要报效应量（差了多少个百分点）和置信区间。
用什么工具：标准库可自助实现 bootstrap（重采样 1000 次取 95% 区间），脚本无需第三方依赖。
产出：`results/significance.csv`（列：对比对/指标/差值/95%CI/是否重叠/结论），并在台账 `结论` 列写明"显著提升 / 无显著差异 / 证据不足"。
判定："看起来高一点"不能写成"优于"；误差棒重叠时只能写 comparable，不得写 slightly better。

### 步骤 8｜回填台账，交棒写作
做什么：把结论回填台账，标 `done`，并把"这张图/这张表支撑哪句话"登记成 `claim → 证据编号` 映射，供 `04-writing.md` 直接调用。
用什么工具：台账文本；映射表 `ledger/claim-evidence.md`。
产出：完整台账 + `claim-evidence.md`，表结构 `论文章节 / 正文句子编号 / 结论 / 证据（表/图/实验ID）/ 是否已被反驳过`。
判定：写进论文的每个数字，都能在这一步的表里反查到实验 ID，反查不到就删掉这句话。

## 输出模板

### 模板 A｜实验台账（`ledger/ledger.md`）

| 实验ID | 日期 | 假设 | 数据集 | 超参 | 指标 | 结论 | 状态 |
|---|---|---|---|---|---|---|---|
| E01-baseline-repro | 2026-09-06 | 在 UAV-IDS 数据集 <名称> 上复现 <基线> 报告的 F1=<值>，偏差应 <1 个点 | <数据集>/<划分> | seed=42; lr=<x>; epoch=<n>; runs=3; cfg=E01-r1.yaml | Accuracy/Precision/Recall/F1(macro)/AUC/FPR | 复现 F1=<值>，偏差 <x>，口径确认为 macro | done |
| E07-N3-ablation | <日期> | 摘除 N3 <模块名> 后，F1 下降 ≥<x> 个点，说明 <机制> 有效 | 同上 | 同 E01，仅移除 <模块>; runs=3; cfg=E07-r1.yaml | F1/Recall/AUC | <下降 x 点，误差棒不重叠 / 无显著差异> | running |

列填写规范：
- **假设**：必须含对照对象与判定阈值；写"验证 N3 有效性"不合格。
- **超参**：只放摘要 + 快照文件名，明细一律进 `configs/`。
- **指标**：写全口径（macro/micro、正类是哪一类的 IDS 场景定义），不写"准确率"这种含糊词。
- **结论**：写数值 + 方向 + 是否显著 + 对哪条 claim 构成支撑或反驳。
- **状态**：`planned / running / done / abandoned`，abandoned 必须同时有 `notes/` 说明。

### 模板 B｜结果记录 CSV 列定义（`results/*.csv`）

必需列（顺序固定，缺失列即为不合格数据源）：

| 列名 | 类型 | 取值/说明 |
|---|---|---|
| `exp_id` | str | 台账实验 ID，外键到 ledger.md |
| `run_id` | str | 单次运行标识，如 `r1`；与 `configs/<exp_id>.<run_id>.yaml` 对应 |
| `seed` | int | 本次 run 的随机种子 |
| `timestamp` | str | ISO 8601，Windows 本地时间带时区或用 `YYYY-MM-DD HH:MM:SS` 统一 |
| `dataset` | str | 数据集名 + 版本 |
| `split` | str | `train / val / test`，或具体 fold 编号 |
| `method` | str | 方法名，`Ours` / `Ours-w/o-N3` / 基线名 |
| `ablation` | str | 消融变体描述，非消融填 `-` |
| `hyperparam` | str | 变化的关键超参，`k=v;k=v`；多个扫点各占一行 |
| `metric_name` | str | 指标名，须与台账口径一致（如 `f1_macro`、`fpr`、`latency_ms`） |
| `metric_value` | float | 该 run 的**单次**观测值，禁止填均值 |
| `unit` | str | 指标单位，无量纲填 `-` |
| `higher_is_better` | bool | 用于绘图时自动判断方向 |
| `n_samples` | int | 计算该指标的样本数，供加权与可读性核查 |
| `source` | str | `self-run` / `reported:<引用>`，抄来的数值必须标 reported |
| `notes` | str | 异常、截断、 skipped 原因等，正常填 `-` |

聚合视图（由必需列派生，不落回 CSV）：`mean`、`std`、`ci_low`、`ci_high`、`n_runs`，在绘图与制表时现算。

- [ ] Y 轴若为比率型指标，已说明是否从 0 起；**截断必须显式标注断点**，不静默截断。

## 质量清单

1. 每条写进论文的结论都能反查到一个 `实验ID`，且该实验状态为 `done`。
2. 主实验与消融实验均 ≥3 次独立运行，报告中为 mean±std，不是最好一次的结果。
3. 随机种子、运行次数、数据划分方式已写入 `configs/` 快照，可按 run 粒度复现。
4. 所有对比方法（含 baselines）用**同一套指标脚本、同一口径**计算；引用他人数值单独标注 `reported:<引用>`。
5. N1–N5 每条 claim 至少有一组独立消融实验，一次只摘一个模块，不存在共用消融。
6. 指标口径在开跑前冻结，与数据集论文/基线论文定义一致，并在正文或图注写明 macro/micro 与正负例定义。
7. 每组关键对比都做了差异判断（误差棒是否重叠 / bootstrap 95% CI），"优于"一词只在有依据时使用。
8. 超参敏感性覆盖关键超参（至少 3 个取值点），并说明主实验取值是怎么选的（不得用 test set 选超参）。
9. 报告了开销：参数量、单样本推理时延、训练时长/显存，测量环境写清（CPU/GPU 型号、batch size）。
10. 图的坐标轴起止、对数轴、截断断点均已注明；不同图之间同一方法配色线型一致。
11. 每张图有 `caption.md`，且图注数值与 `results/` CSV 当前值一致（数据更新后已重画）。
12. `abandoned` 实验未被删除，失败原因已进入 `notes/`，其中可转化为 limitation 的已登记。
13. 主表最佳结果有加粗等标记，且未通过"加粗自己的方法、不加粗基线"以外的方式误导读者（如不放宽基线超参搜索范围）。

## 常见坑

1. **只报最好一次的结果**：跑五次挑最高那次写进论文。审稿人复现就穿帮，且自己后续无法复现。必须报 mean±std。
2. **指标口径不一致**：自家方法用自写脚本算 macro-F1，基线直接抄原论文的 micro-F1 数值，生生造出几个点的"提升"。要么全部自己复现，要么明确标注引用来源并在正文说明不可直接比较。
3. **坐标轴截断误导**：Y 轴从 0.85 起画柱状图，视觉上差距翻十倍。截断可以，但必须画断点符号并说明，比率型指标优先从 0 起。
4. **超参在 test set 上调优**：拿测试集挑阈值再报测试集结果，属于数据泄漏。测试集只在最终评估时碰一次。
5. **消融不干净**：一次改两个模块，或者消融变体的参数量/训练轮次与完整模型不同，导致"下降"其实来自容量或训练不足。消融必须只动目标模块，其余配置完全对齐。
6. **基线被故意做弱**：给基线用默认超参、给自己充分搜索；或不复现基线的关键 trick。审稿人一眼看出，直接质疑可比性。基线的超参搜索预算应与本文方法相当并写入正文。
7. **图注与正文数字漂移**：改了实验没重画图、没改图注，正文表图数字三处不一致。所有数字的唯一真源是 `results/*.csv`，图注与正文从它派生。
8. **把负结果藏掉**：假设不成立就删掉记录。反而是 limitation 与后续工作的素材，且被审稿人问到时无据可查。
9. **只报准确率**：IDS 场景样本高度不平衡，accuracy 99% 可能意味着全判正常。必须同时报 Recall/FPR/AUC/PR-AUC，并说明类别不平衡比例。
10. **开销缺失**：通信/网络类期刊必问时延与可扩展性。不做开销实验，Scalability 与 Complexity 类审稿意见几乎必然出现。
